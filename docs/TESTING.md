# Проверки Mura 1.1

19 октября 2026 года. JDK 25, Gradle 9.6.0, AGP 9.4.1; Android 17 / API 37 arm64 на эмуляторе emulator-5554. Физические Android-устройства при этой проверке не использовались.

| Проверка | Результат |
| --- | --- |
| JVM core:domain | 14/14, включая 5 тестов сетевой криптографии и транспорта |
| Compose / Android app | 9/9, включая публичный интернет-чат и восстановление Activity |
| Android core:data | 5/5, включая миграцию Room 1 → 2 с зашифрованной историей |
| Сервер | 5/5, включая публичный APK и запрет доступа к приватным файлам |
| Release APK / R8 | Собран, постоянная RSA-3072 подпись APK v2 проверена apksigner |
| Android Lint Release | 0 ошибок |
| Android ↔ Apple CryptoKit | Обмен HPKE и проверка подписанных квитанций через публичный HTTPS прошли |
| Форматы MURA1 и Unicode | Совместимость и пароль 6899 проверены JVM / Swift-тестами |

В публичной проверке использовались независимые Android/JVM и Apple CryptoKit идентичности. Это не проверка двух физических телефонов. UI-тест Android отправляет и принимает настоящие конверты через сервер, подтверждает доставку подписью и сохраняет переписку после пересоздания Activity.

`MuraChatInterop` генерирует публичную тестовую фикстуру Apple CryptoKit и проверяет ответ Android. Ключи в фикстуре предназначены только для тестов, не являются пользовательскими и не используются приложением.

Первый общий прогон выявил нестабильный UI-клик в проверке старого локального диалога. Перед кликом тест закрывает клавиатуру и проверяет доступность кнопки; повторный общий прогон 9/9 успешен. Сетевой UI-тест прошёл в обоих прогонах.

Проверки данных: ciphertext в Room, свежие nonce, AAD, избранное при очистке, каскадное удаление, смена ключа и активные Flow, сохранение истории и статуса local при миграции, восстановление сетевой идентичности и зашифрованное хранение настроек.

Проверки сети: взаимное добавление, идемпотентность, подмена и replay запросов, отказ при чужих ключах / изменённом ciphertext / AAD, привязка квитанции к конверту, отзыв разрешения, удаление, TTL и отсутствие доступа к приватным файлам через download-маршруты.

## Воспроизведение

```sh
MURA_TEST_RELAY_URL=https://your-relay.example ./gradlew :core:domain:test
ANDROID_SERIAL=emulator-5554 ./gradlew :app:connectedDebugAndroidTest
ANDROID_SERIAL=emulator-5554 ./gradlew :core:data:connectedDebugAndroidTest
server/.venv/bin/python -m unittest discover -s server -v
./gradlew :app:assembleRelease :app:lintRelease
```

`ChatCryptoTest.appleCryptoKitPublicRelay` требует MURA_IOS_RELAY_CARD и одновременно работающий MuraChatInterop relay; без переменной дополнительный внешний сценарий не выполняется. В описанном прогоне обе переменные и Swift-клиент были заданы; тесты не пропускались.

Логи и JUnit XML сохранены в artifacts/reports. Финальный release отдельно проверяется сценарием scripts/check-release-ui.py: настоящий APK, действия через UI Automator, Apple CryptoKit на другой стороне, статус доставки и повторное открытие после force-stop.

На физических Android ещё не проверены камера, биометрия, Android Sharesheet с внешними приложениями, API 26, TalkBack, большой системный шрифт и производительность на бюджетных устройствах. Независимого аудита безопасности не было. iPhone-проверки описаны в [iOS-отчёте](../ios/docs/TESTING.md).
