# Форматы и криптография

## Публичное кодирование v1

Компактная строка состоит только из ASCII-цифр:

| Поле | Размер |
|---|---:|
| Маркер версии `010` | 3 цифры |
| Длина UTF-8 в байтах | 8 цифр |
| Каждый UTF-8-байт `000`…`255` | 3 цифры на байт |
| CRC32 исходных байтов | 10 цифр |

Отображение разбивает поток по три цифры, разделённые пробелами. Это группировка всего потока; границы полей не обязаны совпадать с группами. Декодер допускает Unicode-пробелы и переносы строк, удаляя их до разбора. Ввод с другими знаками, неверной версией, длиной, байтом вне 0…255, CRC или некорректным UTF-8 отвергается. Нормализация Unicode не применяется: исходная последовательность сохраняется точно. Пустой ввод — явная ошибка. Длина UTF-8 ограничена 131072 байтами.

CRC32 — контроль случайных ошибок. Это публичный код, а не криптография.

## Парольный конверт v1

`MURA1:` + цифровые трёхзначные байты, разделённые пробелами:

| Поле | Размер |
|---|---:|
| Соль SecureRandom | 16 байт |
| Nonce SecureRandom | 12 байт |
| AES-256-GCM ciphertext | длина UTF-8 |
| GCM tag | 16 байт |

Ключ: PBKDF2WithHmacSHA256, 600000 итераций, 256 бит. GCM AAD: `Mura/password/v1;PBKDF2-SHA256/600000;AES256-GCM`. Алгоритмы, параметры и порядок полей фиксированы версией; атакующий не может установить стоимость KDF. Все примитивы предоставляет JCA / Android, собственных криптоалгоритмов нет. Соль и nonce генерируются независимо для каждого сообщения. Неверный пароль и подмена ciphertext вызывают одну нейтральную ошибку аутентификации.

Этот формат — переносимое симметричное парольное шифрование. Он не подтверждает личность собеседника, не обеспечивает forward secrecy и не является протоколом E2EE-мессенджера. Для защиты от офлайн-подбора нужен сильный пароль. Пароль необходимо передать отдельным доверенным способом. Восстановления пароля нет.

Производные массивы ключей и PBEKeySpec очищаются после операции. Строки JVM и внутренние копии JCA не дают гарантированного обнуления; это ограничение явно не скрывается.

## Локальное хранилище

Отдельный неэкспортируемый AES-256-ключ `mura.local.v1` создаётся Android Keystore на устройстве. Каждое поле получает новый сгенерированный провайдером 12-байтовый IV и GCM tag. Формат в SQLite: Base64(IV || ciphertext || tag). AAD отделяет исходный текст, результат, имя контакта и сообщения разных диалогов / направлений.

В Keystore нет постоянного общего ключа пользователей. Парольные ключи не записываются в Keystore, поскольку для обмена они должны выводиться из пароля на обоих устройствах. Локальный Keystore-ключ не экспортируется, не синхронизируется и не используется для сетевого обмена.

Полное удаление: транзакционное удаление таблиц → отбрасывание устаревших снимков Flow → удаление старого alias → генерация нового ключа. Удаление отдельных записей не меняет ключ оставшегося архива. Восстановление старых локальных ciphertext после полного удаления не поддерживается. При потере / повреждении ключа приложение показывает ошибку, а не генерирует замену при чтении.

В Mura 1.1 добавлено разрешение INTERNET для защищённого чата; HTTP запрещён. Секреты не логируются. Backup отключён через allowBackup=false и явные XML-исключения для cloud backup и device transfer на Android 12+. Временные файлы явного экспорта находятся в cache; полное удаление данных очищает и их. Биометрия — блокировка интерфейса, не `setUserAuthenticationRequired` на ключе. Форматы и код нуждаются в независимом аудите перед применением для высокорисковой переписки.

Основания: [Android Cryptography](https://developer.android.com/privacy-and-security/cryptography), [Android Keystore](https://developer.android.com/privacy-and-security/keystore), [Biometric authentication](https://developer.android.com/identity/sign-in/biometric-auth), [Android Auto Backup](https://developer.android.com/identity/data/autobackup).
