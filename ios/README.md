# Mura 1.1 для iOS

Пользовательская инструкция: [первая установка на iPhone и использование Mura](docs/USER_GUIDE_RU.md).

Отдельное нативное приложение на **SwiftUI + SwiftData + CryptoKit + Keychain**, iOS **17+**, iPhone / iPad. Форматы цифрового кодирования `010` и парольного шифрования `MURA1:` совместимы с Android-версией.

## Результат сборки

Проверенное окружение: Xcode 27.1, Swift 6, iOS SDK 27.1, Apple Silicon.

В версии 1.1 добавлен интернет-чат: взаимное добавление контактов по QR / коду, HPKE-шифрование на устройствах, постоянная очередь повторной отправки, проверяемые подписи квитанций доставки. [Описание и запуск сервера](../server/README.md). Пароли для отдельного режима `MURA1:` теперь допускаются от 4 символов, включая `6899`.

- Release-сборка **iOS Simulator / arm64** скомпилирована и локально подписана ad-hoc: `artifacts/mura-ios-simulator.zip` в корне общего проекта.
- Release-сборка **iPhone / arm64** скомпилирована **без подписи**: `artifacts/mura-ios-device-unsigned.zip`. Это промежуточный `.app`, его нельзя установить на iPhone как готовый IPA.
- Debug-сборка **iPhone / arm64** подписана Apple Development для подключённого iPhone 16 Pro: `artifacts/mura-ios-iphone.ipa`. Подпись проверена `codesign --verify --deep --strict`, профиль содержит это устройство и действует до 26 октября 2026 года. Приложение установлено и запущено на iPhone 16 Pro с iOS 18.7.8. Установка, успешный запуск и наличие работающего процесса подтверждены `devicectl`.
- Исходный Xcode-проект: `Mura.xcodeproj`, архив `artifacts/mura-ios-source.zip`.
- Все **13 XCTest-тестов** ядра и транспорта прошли на macOS. Проверка сервера — **4/4**. На iPhone пройден UI-тест интернет-переписки и сохранения после перезапуска с Face ID. Проверен обмен кодами и AES-GCM-конвертами Android → iOS и iOS → Android/JVM.

**Среда запуска iOS Simulator Runtime здесь не установлена.** На физическом iPhone проверены двусторонняя переписка через публичный HTTPS-сервер, статус доставки, восстановление переписки после завершения процесса и возврат после Face ID. Полный регрессионный прогон остальных функций, камера и VoiceOver пока не проверены. Подробности — в [отчёте](docs/TESTING.md).

## Запуск из проекта

1. Откройте `Mura.xcodeproj` в Xcode.
2. Для симулятора установите iOS Simulator Runtime через настройки Xcode, выберите устройство и нажмите Run.
3. Для своего iPhone подключите и разблокируйте устройство, в Signing & Capabilities выберите свою команду разработчика, настройте уникальный Bundle Identifier при необходимости, затем выберите iPhone и нажмите Run. Включите Developer Mode, если Xcode / iOS этого потребуют.
4. При сообщении о недоверенном разработчике подтвердите свой Apple Account в «Настройки → Основные → VPN и управление устройством» на iPhone и повторите запуск.

Локальный проект настроен на Personal Team владельца. Закрытые ключи остаются в системной связке ключей Mac; в исходники они не включаются. Подписанный development IPA предназначен для зарегистрированного iPhone владельца. TestFlight-сборка не создавалась. Симуляторный `.app` не устанавливается на физический iPhone; локальная ad-hoc-подпись для симулятора не заменяет подпись Apple для устройства.

## Сборка и проверки через CLI

Из этой папки:

```sh
swift test --package-path Core
xcodebuild -project Mura.xcodeproj -scheme Mura -configuration Release \
  -destination 'generic/platform=iOS Simulator' -derivedDataPath .derivedData \
  CODE_SIGNING_ALLOWED=NO ARCHS=arm64 build
xcodebuild -project Mura.xcodeproj -scheme Mura -configuration Release \
  -destination 'generic/platform=iOS' -derivedDataPath .derivedData \
  CODE_SIGNING_ALLOWED=NO build
```

Последняя команда проверяет компиляцию для iPhone и **не создаёт устанавливаемую подписанную сборку**. Для установки используйте Signing & Capabilities в Xcode.

`./scripts/package.sh` собирает обе разновидности, запускает XCTest и создаёт архивы. `Simulator.entitlements` применяется только при локальной упаковке симуляторной сборки; для реального устройства Xcode должен сформировать entitlements из вашей подписи / профиля.

## Реализованные функции

- Текст ↔ цифры: полный UTF-8, CRC32, проверка длины / версии / целостности, лимит 128 КиБ.
- Отдельный режим AES-256-GCM: PBKDF2-HMAC-SHA256 / 600000, случайные соль и nonce, контроль GCM tag. Криптографию предоставляют CryptoKit / CommonCrypto / Security.
- Копирование с локальным буфером и временем жизни 2 минуты, вставка, системное меню отправки, UTF-8-файл для длинных результатов, импорт текстового файла.
- QR-генерация Core Image и сканер AVFoundation с запросом разрешения камеры.
- История, поиск, избранное; интернет-чаты, время, непрочитанные, подтверждённая доставка и удаление локальной переписки. Старые локальные диалоги сохраняются как локальные записи.
- Системная / светлая / тёмная темы, RU / KZ / EN, Face ID / Touch ID, очистка старых записей кроме избранного.

Для переписки на обоих iPhone установите обновлённую версию, откройте «Чаты → Мой код» и добавьте коды друг друга через «Новый диалог». Закрытые ключи генерируются автоматически; пароль для чата не нужен. Сервер хранит только зашифрованные конверты до 7 дней. Сообщения приходят, пока приложение открыто и разблокировано; Push/APNs пока нет. Текущий сервер работает на этом Mac через временный HTTPS-туннель: Mac должен быть включён и не спать, адрес может измениться после перезапуска туннеля. Коды `MURA1:` по-прежнему можно передавать отдельно и открывать на Android или iOS.

## Хранение и ограничения безопасности

Содержимое записей и имена контактов шифруются AES-GCM до записи в SwiftData. Локальный случайный 256-битный ключ хранится в Keychain с `WhenUnlockedThisDeviceOnly`, без iCloud-синхронизации. Каталог базы исключён из резервного копирования, CloudKit отключён. При отсутствии ключа у существующего архива показывается ошибка; новый ключ не создаётся вместо потерянного при чтении.

Полное удаление отменяет незавершённое преобразование, удаляет записи, заменяет ключ и очищает экспортированные временные файлы. Соль / парольные ключи не сохраняются. Неизменяемые Swift String и внутренние копии библиотек не позволяют гарантировать обнуление всей памяти. Метаданные времени, типа, связей и флагов избранного не шифруются.

Face ID / Touch ID блокирует интерфейс, а не каждую операцию Keychain. Фоновые снимки маскируются, но запрет любых пользовательских скриншотов не заявляется. Буфер обмена и выбранное приложение отправки получают текст по действию пользователя. Временные файлы экспорта защищены Complete File Protection; файлы старше часа удаляются при следующем запуске / экспорте. Физическое стирание флеш-памяти не гарантируется.

Черновики остаются только в памяти и не восстанавливаются после завершения процесса. Автоочистка проверяется при активации и раз в минуту, пока приложение активно. Нужны отдельные проверки на устройствах: [отчёт](docs/TESTING.md).
